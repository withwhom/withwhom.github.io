# Math Scrap — 스크랩북 게시 스킬

## 목적

공부 세션이 끝난 뒤 그 내용을 https://withwhom.github.io 의 스크랩(포스트)으로 변환한다.
스크랩은 대화록의 복사본이 아니라, 배운 것을 사용자의 언어로 재구성한 짧은 노트다.
"정리해서 다시 쓰는 행위 자체가 공부"라는 것이 이 사이트의 취지다.

## 워크플로우

1. **소재 파악** — 이번 대화(또는 사용자가 붙여넣은 자료)에서 스크랩할 내용을 파악한다.
   여러 주제가 섞여 있으면 무엇을 스크랩할지 먼저 확인한다.
2. **초안 작성** — 아래 형식·문체 규칙에 따라 초안을 만들어 대화에 보여준다.
   이 단계에서는 파일을 만들거나 커밋하지 않는다.
3. **검토** — 사용자의 수정 요청을 반영한다. 내용의 최종 결정권은 항상 사용자에게 있다.
4. **저장** — 사용자가 승인하면("올려줘", "저장해줘", "커밋해줘" 등) 아래 "환경별 동작"을 따른다.

## 포스트 형식

파일 경로: `_posts/YYYY-MM-DD-슬러그.md`
슬러그는 영어 소문자·하이픈으로 3~6단어 (예: `2026-09-13-cosets-lagrange.md`)

front matter는 아래 스키마로 고정한다. 필드를 임의로 추가하거나 이름을 바꾸지 않는다:

```yaml
---
layout: scrap
title: "Cosets and Lagrange's theorem"
date: 2026-09-13
tags: [group theory]
source: "Fraleigh §10"   # 출처(교재·강의·논문)가 있을 때만 넣는 선택 필드
---
```

본문은 소제목 없는 3막 구성으로 쓴다:

- **출발점** — 무엇이 궁금했는지, 어디서 막혔는지 1~2문장
- **핵심** — 정리·증명·계산·통찰. 분량의 대부분을 차지한다
- **남은 질문** — 아직 해소되지 않은 것. 없으면 생략한다

첫 문단(출발점)은 홈 화면의 "Latest scrap" 패널과 목록에 발췌로 그대로 노출된다. 그 자체로 읽히는 1~2문장으로 쓴다.

## 문체와 표기 규칙

- 언어: 영어(사이트 언어). 사용자가 한국어로 써달라고 하면 한국어로 쓴다.
- 분량: 150~400 단어. 스크랩이지 논문이 아니다.
- 수식: 인라인·디스플레이 모두 `$$ ... $$`. 문단 안에 있으면 인라인, 빈 줄로 둘러싸 단독 줄에 두면 디스플레이로 렌더링된다. Markdown 본문에서 `\( ... \)`는 kramdown이 백슬래시를 지워 깨지므로 쓰지 않는다.
- 수식 안에 맨 `|`를 쓰지 않는다. `\lvert G \rvert`, `\vert`, `\mid`를 쓴다. kramdown이 `|`가 있는 한 줄짜리 문단을 표로 오인한다.
- 도함수는 라이프니츠 표기(`df/ds`)를 쓴다. 프라임 표기(`f'`)는 쓰지 않는다.
- 대화록을 그대로 옮기지 않는다. "Claude가 설명하길" 같은 표현 금지 — 사용자의 1인칭 노트로 쓴다.
- 사이트의 목소리에 맞춘다: 건조하고 구체적으로. 거창한 수사("beautiful journey" 류)를 쓰지 않는다.
- 헷갈렸던 지점을 숨기지 않는다. 이 사이트의 모토는 "the confusion is usually the interesting part"다.

## Open questions 처리

초안에 "남은 질문"이 있으면, 저장 시점에 `_data/open_questions.yml`에도 추가할지 사용자에게 물어본다. 형식:

```yaml
- question: "For which groups does the converse of Lagrange's theorem hold?"
  context: "Every subgroup order divides $$\lvert G \rvert$$. When does every divisor come from a subgroup?"
```

질문이 나중에 해결되면: 해당 항목을 목록에서 삭제하고, 해결 과정을 새 스크랩으로 쓰도록 제안한다.

## 환경별 동작

### Claude Code — 저장소 폴더에서 실행 중일 때

1. `git pull`로 원격과 동기화한다(사용자가 GitHub 웹에서 직접 수정했을 수 있다).
2. 파일을 `_posts/`에 생성하고, 합의된 경우 `_data/open_questions.yml`을 수정한다.
3. front matter 문법, 파일명 규칙, KaTeX 구분자가 규격에 맞는지 검증한다.
4. `git add` 후 `scrap: <제목>` 형식의 메시지로 커밋한다.
5. 변경 요약을 보여주고 사용자 확인을 받은 뒤에만 push한다. 확인 없이 push하지 않는다.

### claude.ai 채팅 — 저장소 접근이 불가할 때

1. 완성된 `.md` 파일을 생성해 다운로드로 제공한다.
2. "Claude Code에서 이 파일과 함께 '스크랩으로 추가해줘'라고 하면 커밋까지 처리된다"고 안내한다.

## 주의

- 사이트 디자인 파일(`_layouts/`, CSS, `index.html`)은 이 스킬의 범위 밖이다. 건드리지 않는다.
- 같은 날짜에 스크랩이 여러 개면 슬러그로 구분한다(날짜 중복은 허용된다).
- 수학이 아닌 공부(통계, 프랑스어, 교육학 등)도 같은 규격으로 스크랩할 수 있다. tags로 구분하면 된다.
